# Delta Review Rules

## Goal

二次复核的目标不是重写首轮结果，而是补充首轮遗漏的新增 finding。

## Re-read Before Judging

1. 重新读取招标文件和投标文件。
2. 重新建立主体基线。
3. 若首轮 requirements 明显偏少或只覆盖少量显眼问题，先补足阅读全文，再判断哪些遗漏项值得新增。

## Priority Areas

优先复核首轮最容易漏掉的位置：

- 招标人 / 投标人信息段
- 开户行、账户名、账号段
- 授权委托页和法定代表人页
- 签字盖章页、落款页
- 承诺函抬头 / `致：`
- 封面、营业执照
- 资格审查申请书
- 投标函
- 投标保证金交纳证明
- 基本账户证明
- 开标一览表、分项报价表
- 技术 / 商务偏离表

## Mandatory Checks

- 若首轮只给了泛化“需人工核验主体一致性 / 项目信息一致性”，但文档中已有明确字段和值，二次复核必须补成字段级 finding。
- 若同一主体字段在多处出现不同值，必须新增 finding。
- 若字段标签和值类型不匹配，必须新增 finding。
- 若模板文书中的 `致：`、项目名称、招标编号、主体字段填错对象，必须新增 finding。
- 若只是首轮同一事实的改写，不得作为新增项。

## Output Rules

- 只输出新增项。
- `requirement_id` 必须复用首轮已有 requirement。
- 不得新增 requirement 编号。
- 新增项上限按“少而准”处理；无新证据时返回空数组。

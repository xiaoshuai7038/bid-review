# Domain Rules

## Tender Requirement Extraction

- 优先读取招标文件中的：
  - 投标人须知
  - 技术要求
  - 投标文件格式 / 模板章节
- 提取针对投标文件内容本身的硬性要求。
- 尽量覆盖：
  - 资格资质
  - 类似项目业绩
  - 报价与税务
  - 工期 / 交付
  - 签字盖章
  - 格式完整性
  - 技术响应
  - 服务承诺

## Subject Baselines

先建立主体基线，再写 finding：

- 招标人 / 采购人：
  - 名称
  - 税号 / 统一社会信用代码
  - 银行账户信息（如有）
- 投标人：
  - 名称
  - 统一社会信用代码
  - 税号 / 纳税人识别号
  - 法定代表人
  - 授权代表 / 委托代理人
  - 开户银行
  - 账户名
  - 账号
- 联合体成员（如有）：
  - 成员名称
  - 身份和角色

优先使用营业执照、封面、投标函、资格审查申请书、授权委托书、保证金或账户证明等权威位置建立基线。

## Mandatory Checks

- 角色 / 位置一致性：
  - 招标人信息不能写进投标人位置
  - 投标人信息不能写进招标人位置
  - 开户银行、账户名、账号要放在正确字段
- 同一主体跨全文一致性：
  - 投标人名称
  - 统一社会信用代码
  - 税号
  - 法定代表人
  - 授权代表
  - 开户银行
  - 账户名
  - 账号
- 字段标签和值类型一致性：
  - `开户银行` 应填银行名
  - `账户名` 应填账户主体
  - `账号` 应填账号串
  - 法定代表人 / 授权代表应填自然人姓名
- 模板字段角色一致性：
  - `致：`
  - 项目名称
  - 招标编号
  - 投标人 / 法定代表人 / 委托代理人
  - 投标保证金与基本账户字段
  - 技术 / 商务偏离表

## Severity

- `non_compliant`：
  - 明确不符合
  - 明显主体错位
  - 模板字段误填
  - 关键字段缺失
- `risk`：
  - 有较强风险但证据还不完全闭合
- `needs_manual`：
  - 证据不足、模糊或截图不可读
